## Analysis-protocol decisions (2026-07-30)

| Item | Decision | Why |
|---|---|---|
| Selection pools | Full selector factorial (6 Vendi orders, coverage, facility location, random x20) on the seeded 40-chain pool; on the full 1024 pool the core quartet (VS_1, VS_inf, coverage, facility location) on K_emb and K_ans. | Greedy over 1024 candidates costs ~100x the 40-pool run; the blueprint names both pool sizes, and the factorial's alpha/q sweeps live on the 40-pool. |
| Coverage selection objective | Greedy pseudo log-det on the **raw** subset spectrum (B3's convention; equals DPP log-volume on non-singular subsets). The cached **measure** keeps the normalized convention pinned by harness T4; both are stored (`pseudo_logdet`, `pseudo_logdet_raw`, differing by exactly r log n). | The two blueprint clauses pin different conventions; storing both keeps every downstream comparison reproducible. |
| MATH equivalence classes | One sympy canonicalization per distinct answer (persistent oracle process, 5 s timeout, string fallback); class-vs-gold correctness uses simplify(a-b)==0 semantics via the same oracle. | All-pairs simplify() over ~100 distinct answers per question is quadratic; canonical forms give the same partition at linear cost. |
| PRM verifier arm | Not run. Verifier best-of-n uses the mean token-logprob arm only (the blueprint's cautionary arm). | Scoring 6 x 60-96 x 1024 chains with an open PRM does not fit the 12 h A100 budget. Listed as a limitation. |
| E3 sample-size sweep | 24 questions per cell; 100 seeds for n <= 160, 40 seeds above. | eigh(1024) x 100 seeds x all questions is ~10 h of CPU; variance of the seed-mean is already < 1% at 40 seeds. |
| R6 decision unit | Signals score whether the full-1024-pool majority vote is correct. | Matches the deck's construction; budgeted votes appear separately in R1. |
| **Every arm averaged over 5 subsample draws** | The 40-chain selection pool is drawn with seeds 0-4; each objective *and* the 20-seed random baseline are evaluated on all five draws and averaged, so every cell reports a mean success rate rather than one bool. | Found by re-running a "significant" result under different draws: on the 13-question minority stratum of Qwen2.5-1.5B/GSM8K, pass@k for VS_inf gave delta = **+0.185** (CI [+0.096, +0.300], p = 0.001) at subsample seed 0, **+0.104** (n.s.) at seed 1 and **-0.169** at seed 2. Averaging only the random arm (the earlier protocol) left each treatment arm carrying the noise of a single arbitrary draw while the baseline had 20, which is both unfair and, on small strata, large enough to flip the sign of the reported effect. Any effect that does not survive this averaging was never real. |
| **Primary embedding kernel is question-centred** | Headline embedding results use `K_emb` built from chains re-expressed as deviations from *their own question's* centroid and leading direction. The blueprint's corpus-level anisotropy sweep (c = 0..3, fitted over the whole model x dataset chain corpus) is kept as the ablation arm (P-A4). | Measured on the first full bank (40 questions, pool 40, k=8): raw `K_emb` has mean top-eigenvalue share **0.940** and mean VS_1 = **1.49** effective modes among 40 genuinely different chains, with two objectives choosing the *identical* set on 22% of questions. The corpus-level correction barely moves it (c=1: share 0.875, VS_1 = 2.15; c=3: 0.873, 2.17) — corpus-wide directions are **not** the cause. Question-centring gives share **0.514**, VS_1 = **9.29**, identical-selection rate **0.060**. The concentration is therefore question-specific — every chain in a pool answers the same problem — so measuring diversity *among* those chains requires removing the question's own content. An earlier version of this entry misattributed the question-centred numbers to the corpus-level sweep; both arms are now measured separately and reported side by side. |
| Greedy VS_0 on a continuous kernel is degenerate | Reported but never treated as a headline winner. | Richness equals the subset size for any set of distinct embeddings, so every candidate ties and greedy VS_0 reduces to "take the lowest-indexed chains". It is a meaningful selector only on kernels with exact ties, i.e. `K_ans`. |
